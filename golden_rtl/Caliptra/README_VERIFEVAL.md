## Synthesis / elaboration verification

Caliptra's own canonical top-level testbench file list
(`src/integration/config/caliptra_top_tb.vf`, upstream's own file — used verbatim, generated by
VCS and checked in) enumerates every RTL/testbench file needed to build `caliptra_top_tb`, the full
chip-level simulation top (which instantiates `caliptra_top`, the actual DUT, as
`caliptra_top_dut`). We used it directly as the input to Verilator, mirroring the flags used by
upstream's own `verilator-build` Make target (`tools/scripts/Makefile`) as closely as possible:

```bash
cd golden_rtl/Caliptra/caliptra-rtl
export CALIPTRA_ROOT=$(pwd)
export CALIPTRA_PRIM_ROOT=$CALIPTRA_ROOT/src/caliptra_prim_generic
export CALIPTRA_PRIM_MODULE_PREFIX=caliptra_prim_generic

# The upstream .vf also references ${CALIPTRA_AXI4PC_DIR}/Axi4PC.sv -- the ARM AXI4 Protocol
# Checker, which upstream's own README explicitly states is proprietary ARM IP and therefore
# intentionally NOT distributed in the caliptra-rtl repository (must be licensed/downloaded
# separately by integrators). We exclude just that one line for the lint run below; this is a
# documented, expected external dependency gap, not a gap in our vendoring.
grep -v AXI4PC_DIR src/integration/config/caliptra_top_tb.vf > /tmp/caliptra_top_tb_lint.vf

verilator --lint-only -Wno-fatal --top-module caliptra_top_tb \
  +libext+.v+.sv +define+RV_OPENSOURCE --timescale 1ns/100ps --timing \
  +define+CALIPTRA_TOP_TB +define+CALIPTRA_TOP=caliptra_top_tb \
  +define+RV_TOP=caliptra_top_tb.caliptra_top_dut.rvtop \
  -f /tmp/caliptra_top_tb_lint.vf \
  -f src/integration/config/caliptra_top_tb.vlt   # upstream's own lint waiver file
```

**Result:** `verilator --lint-only` (Verilator 5.044) elaborates **778 modules** — the entire
Caliptra chip: VeeR-EL2 RISC-V core, AES, ECC, HMAC/HMAC-DRBG, SHA-256/384/512(-masked), KMAC,
CSRNG/entropy_src/EDN/DOE entropy chain, key/PCR/data vaults, lifecycle controller, AXI/AHB-Lite
buses, and the full Adams-Bridge ML-DSA/ML-KEM post-quantum accelerator (NTT, samplers, SHA3,
Barrett reduction, etc.) — with **exit code 0 and zero errors**. Remaining diagnostics are the
usual categories of benign, non-fatal lint warnings expected on a design this size (`LATCH`,
`WIDTHEXPAND`/`WIDTHTRUNC`, `MULTIDRIVEN`, `CMPCONST`, `ASCRANGE`, `UNOPTFLAT` — mostly in
generate-block/array-of-instances code and reg-block boilerplate), none of which are unsupported
constructs or missing/undefined references. No vendored source file was modified to achieve this.

Two Verilator/tooling notes worth recording (neither required editing any vendored file):

1. Two module-selection macros (`` `PA_WIDTH``-style patterns don't apply here, but analogous
   `` ${CALIPTRA_PRIM_MODULE_PREFIX}``-style filename templating does) are resolved purely via
   shell/Verilator environment-variable substitution in the `.vf` file, exactly as the upstream
   Makefile does — no substitution logic was added by us.
2. Caliptra's own assertion-macro header (`caliptra_prim_assert.sv`) already auto-selects a
   Verilator-safe (`` `ifdef VERILATOR``) no-op implementation of its `` `CALIPTRA_ASSERT`` family
   for exactly this reason (Verilator's SVA subset doesn't support some of the boolean-abbreviation
   / cycle-delay-range sequence syntax used in a handful of `caliptra_prim`/`abr_prim`
   OpenTitan-derived assertions) -- so this is an upstream-anticipated, already-solved
   compatibility path, not something we patched around. The one thing to *avoid* is passing VCS's
   `+define+CLP_ASSERT_ON`/`+define+ABR_ASSERT_ON` (which live in `VCS_COMP_OPTS`, not the
   Verilator target's flags) to Verilator, since that activates the full SVA assertion bodies that
   Verilator's `--lint-only` cannot parse; the repro above intentionally omits them, matching
   upstream's own `verilator-build` target.
